## Production sequence

Cycle 5 followed the frozen order:

1. isolated staging RC deployment;
2. immutable RC tag/archive and signed RC ReleaseManifest;
3. original-color three-material full-chain acceptance;
4. immutable stable tag/archive;
5. production Server/Core/shared ingress dark deployment;
6. approved 50-credit paid canary, idempotent replay and refund rollback;
7. stable Core ReleaseManifest activation;
8. formal public-channel clean reinstall and real Server/Core preflight.

The stable release registry and signing configuration are stored in the
production deployment workflow. A later routine Core redeploy preserved the
stable endpoint and the public verifier accepted the same signed Manifest.

## Public-channel smoke

The final smoke used isolated install, Home and temporary Keychain roots. It
verified:

- exact stable version, tag, commit, archive and keyset metadata;
- macOS managed installation with Node.js 24;
- `creatorcut version`, `creatorcut doctor` and
  `creatorcut update check`;
- a real Director preflight reporting Protocol v1 compatibility and the
  `creatorcut.director.plan` catalog price of 50 credits;
- Core and Server new-work gates both remained closed.

Only the content-addressed package download cache was reused. No existing
CreatorCut project, media, Kitchen or managed install was read, reset or
overwritten.

## Availability boundary

Stable public managed installation is active. Paid new Director generations
are not generally open: production keeps both the shared Core product gate and
the private Server generation gate closed. Opening commercial workload
admission requires a separately approved operation and is not implied by this
release.
