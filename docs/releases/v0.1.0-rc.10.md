# CreatorCut v0.1.0-rc.10

This candidate supersedes `v0.1.0-rc.9` after the real public-channel install
gate found that the installer built with Node.js 24 but its generated launcher
later resolved `node` from the caller's ambient `PATH`.

## Managed runtime correction

- Resolve and validate the exact Node.js 24 executable during installation.
- Generate the managed launcher with that absolute executable instead of an
  ambient `node` command.
- Prepend the pinned Node.js directory to the managed process `PATH`, so
  updater builds and version smokes also remain on Node.js 24.
- Keep the verified tag, commit, canonical archive, release keyset, signed
  Manifest and local-project isolation contracts unchanged.
- Preserve the RC9 original-color renderer correction without adding any
  automatic color processing.

## PDCA evidence

- The Check phase ran the installed command from a normal terminal and observed
  Node.js 25 even though the installer had validated Node.js 24.
- The regression fixture now puts a failing fake `node` first on the caller's
  `PATH`; the installed CreatorCut launcher must still execute successfully
  through the pinned Node.js 24 path.
- RC10 must repeat full public verification, canonical archive validation,
  signed staging installation and the three accepted real-material checks.

## Release status

- This correction changes only managed runtime selection. It does not alter
  Director policy, credits, rendering, captions, music or original audio.
- Staging commercial gates remain closed while the RC10 Manifest is prepared.
- No stable release or production activation is authorized by this candidate.
