# CreatorCut v0.1.0-rc.4

This candidate supersedes `v0.1.0-rc.3` for Cycle 5 staging acceptance.

## Fixed since rc.3

- `creatorcut auth login` now uses `security -i` and sends the complete
  add-password command only through stdin. A bare `security -w` failed, while
  omitting `-w` stored an empty value; both were caught by real Keychain
  acceptance.
- The credential contract test now fixes `security -i` as the complete argument
  vector and continues to prove that the API key is present only on stdin.
- `CREATORCUT_KEYCHAIN_PATH` can point acceptance and automation at an isolated
  non-default Keychain. Every read, write and delete then targets that file
  explicitly and never changes the user's login Keychain or search list.
- RC acceptance includes a real disposable Keychain probe and the installed
  public CLI login path, not only an injected command-runner unit test.

The release trust chain, M1 product scope and remaining Cycle 5 acceptance gates
are unchanged.
