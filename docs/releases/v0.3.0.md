# AgentMesh-CreatorCut v0.3.0

This release hardens local project ownership and concurrent mutation recovery.
It does not activate the experimental internal-project migration path.

## User-visible changes

- New projects bind their canonical metadata to a generation-tracked public
  storage-authority marker and durable mutation journal.
- Existing public projects created by v0.2.1 remain supported. Before the first
  v0.3.0 status or mutation, confirm the one-time local metadata adoption:

  ```bash
  creatorcut project adopt-public \
    --project /path/to/project.creatorcut \
    --confirm-local
  ```

- Adoption verifies the complete project/history chain, preserves media and
  canonical metadata bytes, and writes only the local lock, initial journal,
  and authority marker. It rejects internal, pending, staged, torn, tampered,
  or multi-generation state.
- `--confirm-local` confirms that all v0.2.1 CreatorCut processes have exited
  and no legacy preview, Director request, export, or transcription task is in
  progress. Do not mix v0.2.1 and v0.3.0 processes on one project. Completed
  generated assets, previews, and transcription work stay byte-for-byte in
  place and outside metadata digest, backup, restore, and deletion. Frozen
  Windows generated-asset paths retain their bytes; moving them to POSIX before
  adoption is not a supported path-translation workflow.
- Public runtime, Director, media, transcription, CLI, and MCP mutations now
  share generation/digest conflict checks and crash-recovery state.
- Managed builds remove stale `dist` output before compiling the tagged source.

## Compatibility and boundaries

- CreatorCut Protocol v1, signed Director envelopes, media locality, secure
  credential storage, and the 50-credit Director boundary are unchanged.
- `project migrate-internal` and `project rollback-internal` fail before
  credentials or project resolution. The native whole-tree swap code in this
  source release is a synthetic prototype and is not built, installed, or
  invoked by the product.
- The JavaScript project lock coordinates cooperative same-user CreatorCut
  clients. It rejects static symlink and identity substitution and fails closed
  when it detects a concurrent replacement, but an actively hostile same-UID
  process swapping lock-directory ancestors inside a filesystem syscall window
  is outside this release's threat model. Do not run untrusted code under the
  same account against an open project.
- Project state must be stored on a local filesystem with same-volume atomic
  rename and reliable SQLite/OS file locking. FAT/exFAT, network shares, and
  cloud-synced virtual filesystems are not supported project locations; the CLI
  fails closed instead of running without a lock.
- On Windows, Node 24 cannot flush directory handles. CreatorCut still syncs
  file contents before rename and covers process-crash recovery, but sudden
  power-loss durability on Windows is not claimed by this release.
- Windows private preview and transcription work operates under the project
  directory's inherited ACL; POSIX-only `0700`/`0600` mode tightening neither
  creates nor verifies a Windows DACL. Keep projects in a current-user-private
  local directory.
- No real project was opened or migrated to produce this release. The adoption
  compatibility gates use isolated temporary v0.2.1-format fixtures.
